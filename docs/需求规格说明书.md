## 1. 引言

### 1.1 编写目的

本文档定义 SauceDemo UI 自动化测试项目的建设目标、范围、功能需求、非功能需求、数据与接口要求、测试覆盖要求及验收标准，作为设计、开发、测试与验收的共同依据。

预期读者：测试开发工程师、自动化维护人员、项目评审人员及后续接手人员。

### 1.2 项目背景

Web UI 回归测试依赖人工重复操作，存在执行成本高、结果不一致、失败现场难追溯的问题。本项目以公开、稳定、无需特殊权限的 SauceDemo 演示站点为载体，建设一套基于 Selenium + pytest + YAML 的 Page Object 自动化工程，验证「登录 → 商品 → 购物车 → 结账 → 完成」核心链路的自动化闭环，并形成可复用的工程规范。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| PO / Page Object | 页面对象模式，将页面定位、等待与用户动作封装为类 |
| SUT | 被测系统，本项目为 SauceDemo |
| 显式等待 | 等待某个具体条件成立，如元素可见、URL 包含指定片段 |
| 隐式等待 | WebDriver 全局查找元素的兜底等待，本项目固定为 0 |
| 冒烟集 | 覆盖最关键链路的最小用例集合，提交前执行 |
| 失败现场 | 失败时的截图、页面 URL/标题、浏览器版本、日志等诊断信息 |
| P0/P1/P2 | 用例优先级，P0 最高 |

### 1.4 参考文档

1. `README.md`：工程结构、安装运行、调试与验收说明。
2. `SauceDemo_UI自动化项目方案.md`：项目实施方案与阶段性落地步骤。
3. SauceDemo 站点公开页面与真实 DOM（定位器核对依据）。

## 2. 被测系统与项目范围

### 2.1 被测系统概述

SauceDemo 是一个公开的电商演示站点，提供以下可自动化流程：

```text
登录 → 商品列表 → 加入购物车 → 购物车 → 结账信息 → 订单概览 → 订单完成
```

站点自带标准账号、锁定账号、错误账号等演示数据，支持商品排序、购物车增删、结账必填校验等场景，适合作为 UI 自动化框架的验证载体。

### 2.2 本期范围

| 范围 | 内容 |
|---|---|
| 纳入 | 登录正向与负向、商品列表与排序、购物车增删与状态、单/多商品结账、结账必填校验、取消结账、下单后状态清理 |
| 纳入 | 配置管理、浏览器管理、PO 分层、YAML 定位器与数据、失败诊断、HTML 报告、CI 示例 |
| 不纳入 | 接口自动化、数据库校验、移动端、视觉回归、性能压测、多环境真实业务系统 |
| 不纳入 | 并行执行、分布式执行、账号体系与权限管理 |
| 浏览器 | Chrome / Edge / Firefox 均提供创建能力；本期验收基线为 Edge 无头模式 |

### 2.3 用户角色

| 角色 | 关注点 |
|---|---|
| 测试开发工程师 | 框架能力、用例组织、定位器维护、失败诊断 |
| 回归执行人员 | 一条命令运行、报告与结果判定 |
| 项目评审人员 | 覆盖范围、验收证据、风险与边界 |
| 后续维护人员 | 目录职责、扩展方式、配置与数据入口 |

### 2.4 假设与依赖

1. SauceDemo 站点可公网访问，页面结构与公开账号在项目周期内保持基本稳定。
2. 运行机器已安装 Chrome、Edge、Firefox 中至少一种浏览器。
3. 首次运行可联网，Selenium Manager 能下载匹配的浏览器驱动。
4. Python 版本为 3.11 及以上，项目验证版本为 3.13.12。
5. CI 环境可使用 GitHub Actions 提供的浏览器镜像；当前仅提供工作流示例，尚未在托管仓库实际运行。

### 2.5 约束

1. SauceDemo 为共享演示站点：禁止并发压测、批量造数或破坏共享状态。
2. 每条用例必须使用独立浏览器会话，不依赖前序用例的购物车状态。
3. 禁止使用固定 `sleep()` 解决同步问题，统一使用显式等待。
4. 测试代码不得硬编码 XPath/CSS，定位器必须集中在 YAML。
5. 真实凭据不得写入仓库；演示站点仅使用公开演示账号，并支持环境变量覆盖。
6. 运行产物（报告、截图、日志）不得提交到版本库。

## 3. 业务需求

| 编号 | 业务需求 | 优先级 | 成功衡量 |
|---|---|---|---|
| BR-01 | 建立可重复执行的核心购买链路 UI 回归能力 | Must | 一条命令跑通登录到下单完成 |
| BR-02 | 降低站点改版与定位器变化带来的维护成本 | Must | 常规改版只修改定位器 YAML，不改测试代码 |
| BR-03 | 失败时能够快速定位是站点、环境还是用例问题 | Must | 失败可获取截图、URL、浏览器版本、日志与报告 |
| BR-04 | 本地与 CI 使用同一套配置和命令 | Should | CI 工作流可复用 `pytest` 命令与配置 |
| BR-05 | 形成可交付、可教学、可扩展的工程样例 | Should | 文档、架构、用例与运行记录完整 |

## 4. 功能需求

优先级说明：M = Must（必须）、S = Should（应该）、C = Could（可选）。

### 4.1 配置管理

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-CFG-01 | 默认配置与环境配置分离 | M | 默认配置保存浏览器、超时、产物与日志设置；环境文件保存 `base_url` | `config/config.yaml` 与 `config/env/demo.yaml` 职责清晰 |
| FR-CFG-02 | 运行环境可选 | M | 通过 `--env=<name>` 选择 `config/env/<name>.yaml` | `pytest --env=demo` 正常；不存在时启动即报错并指出文件 |
| FR-CFG-03 | 配置优先级明确 | M | 命令行 > 环境变量 > 环境 YAML > 默认配置 | 覆盖项生效且不污染其他配置 |
| FR-CFG-04 | 配置启动校验 | M | 校验 URL 协议、浏览器枚举、headless 类型、窗口格式、超时为正数、隐式等待为 0 | 非法配置在收集/启动阶段失败，错误信息可读 |
| FR-CFG-05 | 环境变量覆盖 | S | 支持 `UI_BASE_URL`、`UI_BROWSER`、`UI_HEADLESS` | 不修改文件即可切换地址、浏览器、无头模式 |
| FR-CFG-06 | 配置文件深度合并 | S | 环境文件只覆盖指定子项，其余继承默认配置 | 嵌套配置合并后结构完整 |
| FR-CFG-07 | 配置层自动化单元测试 | S | 不启动浏览器即可验证合并、优先级、校验与归档逻辑 | `pytest -c pytest-unit.ini` 32 条通过 |

### 4.2 浏览器与驱动管理

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-BRW-01 | 浏览器自动探测 | M | `browser.name=auto` 时按 Chrome → Edge → Firefox 顺序探测本机浏览器 | 无 Chrome 的机器自动使用 Edge 并记录日志 |
| FR-BRW-02 | 多浏览器创建能力 | S | 支持 Chrome、Edge、Firefox 的 Options 创建分支 | 可用 `--browser` 显式指定；本期仅 Edge 完成全量验收 |
| FR-BRW-03 | 驱动自动解析 | M | 通过 Selenium Manager 获取匹配驱动，不手工维护驱动路径 | 首次联网可自动下载，后续复用缓存 |
| FR-BRW-04 | 统一基础参数 | M | 创建后设置窗口尺寸、页面加载超时、隐式等待为 0 | 框架内无隐式等待与显式等待混用 |
| FR-BRW-05 | 会话生命周期可靠 | M | 每条用例独立创建浏览器，teardown 无论成功失败都执行 `quit()` | 失败场景下进程不残留、下一用例不受影响 |
| FR-BRW-06 | 无头与有头切换 | M | 默认无头；`--headed` 切换为有头，便于调试 | 同一条用例可用两种模式运行 |

### 4.3 分层与 Page Object

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-PO-01 | 页面对象按页面拆分 | M | 登录、商品列表、商品详情、购物车、结账信息、结账概览、完成页各自独立 | 页面类职责单一，命名与页面一致 |
| FR-PO-02 | 页面对象只做动作与查询 | M | 页面对象封装用户动作和页面状态查询，不写业务断言 | 所有断言仅出现在 `tests/` |
| FR-PO-03 | BasePage 通用能力 | M | 提供定位解析、显式等待、点击、输入、取文本、存在性判断、导航 | 页面对象不直接调用 `find_element` 或 `sleep` |
| FR-PO-04 | 动态元素定位 | M | 支持按商品名定位商品行内的加购/移除/价格/数量元素 | 商品名通过命名参数注入 XPath 模板 |
| FR-PO-05 | 登录页对象能力 | M | 打开登录页、提交账号、读取错误提示 | 登录成功与三类失败提示均可查询 |
| FR-PO-06 | 商品页对象能力 | M | 等待加载、加购、移除、购物车角标、进入购物车、排序、商品名/价格查询、打开详情、登出 | 支持 6 个商品的列表、排序与详情跳转校验 |
| FR-PO-07 | 购物车对象能力 | M | 商品列表、数量、价格、移除、空车等待、继续购物、刷新、进入结账 | 清空购物车后可等待并确认空状态 |
| FR-PO-08 | 结账对象能力 | M | 填写/提交客户信息、读取错误、取消；概览金额与完成按钮；完成页文案与返回 | 覆盖单/多商品结账与取消流程 |
| FR-PO-09 | 商品详情对象能力 | M | 读取名称与价格、加购、移除、返回列表、购物车角标 | 详情页加购/移除后与列表页状态一致 |

### 4.4 定位器管理

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-LOC-01 | 定位器集中管理 | M | 每个页面一个 YAML 文件，测试代码不出现 XPath/CSS 字符串 | 全仓库检索测试目录无定位器字面量 |
| FR-LOC-02 | 定位策略受控 | M | 支持 id、name、class name、css selector、xpath、link text、partial link text、tag name | 非法策略加载时抛出明确错误 |
| FR-LOC-03 | 稳定属性优先 | M | 优先使用站点提供的 `data-test` 与 id | 26 条用例的定位器均基于真实 DOM 核对 |
| FR-LOC-04 | 定位器结构校验 | M | 加载时校验 `by`、`value` 存在且非空 | 缺少字段时在启动阶段失败 |
| FR-LOC-05 | 改版维护成本可控 | S | 站点改版时只更新对应页面 YAML，页面对象与用例通常不变 | 有明确的定位器核对与更新流程 |

### 4.5 用例执行与数据驱动

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-EXE-01 | 标准命令执行 | M | 使用 pytest 发现并执行用例，支持指定文件、用例、关键字 | `pytest`、`pytest tests/test_login.py -v` 可用 |
| FR-EXE-02 | 标记与分组执行 | M | 支持 `smoke / regression / p0 / p1 / p2` 标记 | `-m smoke` 执行 4 条，`-m regression` 执行 26 条 |

### 4.6 失败诊断与报告

| 编号 | 需求 | 优先级 | 需求描述 | 验收要点 |
|---|---|---|---|---|
| FR-DIA-01 | 失败截图 | M | 用例失败时在浏览器退出前保存截图 | `reports/runs/<run_id>/screenshots/<时间戳>_<用例ID>.png` 存在且可打开 |
| FR-DIA-02 | 失败元信息 | M | 保存用例 ID、时间、URL、标题、环境、浏览器与版本 | 同名 JSON 文件字段完整，含 `run_id` |
| FR-DIA-03 | 可选页面源码 | C | 配置开启时保存失败页面 HTML | 默认关闭，开启后写入 `reports/runs/<run_id>/page_source/` |
| FR-DIA-04 | 结构化日志 | M | UTF-8 日志记录配置、导航、关键业务动作与失败现场 | `logs/runs/<run_id>/ui-tests.log` 可读，包含测试执行链路 |
| FR-DIA-05 | 敏感信息脱敏 | M | 日志不记录密码，输入动作只记录字段名与长度 | 日志与报告中检索密码结果为 0 |
| FR-DIA-06 | HTML 报告 | M | 生成单文件报告，包含状态、耗时、失败堆栈与捕获日志 | `reports/report.html` 可直接在浏览器打开 |
| FR-DIA-07 | 产物不污染仓库 | M | `reports/`、`logs/` 加入版本库忽略规则 | `.gitignore` 生效，仅保留占位文件 |
| FR-DIA-08 | 失败产物按构建归档 | S | 用 `UI_RUN_ID` 标识一次运行，报告、日志与失败产物归档到同一目录 | `reports/runs/<run_id>/run.json` 汇总本次结果；`reports/runs/latest.txt` 指向最近一次 |
| FR-DIA-09 | 失败证据内嵌报告 | S | HTML 报告中直接展示失败截图、现场元信息与日志尾部，无需翻找归档目录 | 失败用例的报告行含截图缩略图与「失败现场信息」「运行日志尾部」链接 |

## 6. 数据与接口需求

### 6.1 配置文件结构

`config/config.yaml` 必填结构：

```yaml
browser:
  name: auto            # auto | chrome | edge | firefox
  headless: true
  window_size: "1440,1000"
  page_load_strategy: normal
timeouts:
  implicit: 0
  explicit: 10
  page_load: 30
artifacts:
  screenshot_on_failure: true
  save_page_source_on_failure: false
logging:
  level: INFO
```

环境文件只需提供：

```yaml
base_url: "https://www.saucedemo.com"
```

### 6.2 命令行接口

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--env` | 环境名 | `demo` | 读取 `config/env/<env>.yaml` |
| `--browser` | `auto/chrome/edge/firefox` | 配置文件值 | 覆盖 `browser.name` |
| `--headed` | 开关 | 关闭 | 覆盖为有头模式 |
| `-m` | 标记表达式 | 无 | 按 smoke/p0/p1/p2/regression 筛选 |
| `-k` | 关键字表达式 | 无 | 按用例名筛选 |

### 6.3 环境变量

| 变量 | 类型 | 作用 |
|---|---|---|
| `UI_BASE_URL` | URL | 覆盖被测地址 |
| `UI_BROWSER` | 枚举 | 覆盖浏览器 |
| `UI_HEADLESS` | `true/false` | 覆盖无头设置 |
| `UI_RUN_ID` | 字符串 | 指定本次运行 ID，决定 `reports/runs/` 与 `logs/runs/` 归档目录；未设置时用时间戳 |
| `SAUCE_STANDARD_USERNAME` / `SAUCE_STANDARD_PASSWORD` | 字符串 | 覆盖标准账号 |
| `SAUCE_LOCKED_USERNAME` / `SAUCE_LOCKED_PASSWORD` | 字符串 | 覆盖锁定账号 |

### 6.4 运行产物

| 产物 | 路径 | 生成时机 |
|---|---|---|
| HTML 报告 | `reports/report.html` | 每次 pytest 运行结束 |
| 构建归档目录 | `reports/runs/<run_id>/` | 每次运行结束；含报告、`run.json`、日志与失败产物 |
| 最近一次归档指针 | `reports/runs/latest.txt` | 每次归档结束 |
| 失败截图 | `reports/runs/<run_id>/screenshots/*.png` | 用例失败且配置开启 |
| 失败元信息 | `reports/runs/<run_id>/*.json` | 用例失败且配置开启 |
| 页面源码 | `reports/runs/<run_id>/page_source/*.html` | 配置显式开启且用例失败 |
| 运行日志 | `logs/runs/<run_id>/ui-tests.log` | 每次运行写入 |
| 累计日志 | `logs/ui-tests.log` | 每次运行追加写入 |

`run_id` 优先级：`UI_RUN_ID` 环境变量 > 时间戳（`%Y%m%d-%H%M%S`）。归档时对 `run_id` 做字符白名单清洗，避免路径穿越。

### 6.5 定位器结构

```yaml
<locator_name>:
  by: css selector | xpath | id | ...
  value: "<selector>"
```

动态定位器使用 `{product}` 占位符，由 `BasePage.locator(name, **params)` 填充。

### 6.6 测试数据

| 文件 | 结构 | 用途 |
|---|---|---|
| `testdata/checkout_cases.yaml` | 列表：`id/first_name/last_name/postal_code/expected_error` | 结账必填校验 3 组 |
| `testdata/login_cases.yaml` | 列表：`id/empty_field/expected_error` | 登录空字段 2 组，非空账号由 fixture 注入 |

## 11. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|---|---|---|---|
| SauceDemo 页面改版导致定位器失效 | 用例失败 | 中 | 定位器集中 YAML；优先 `data-test`；失败截图与源码辅助快速修正 |
| 公网访问慢或抖动 | 等待超时、执行变慢 | 中 | 显式等待具体状态；超时可配置；避免固定 sleep |
| 共享演示站状态被他人影响 | 结果不稳定 | 低 | 独立会话、串行执行、不依赖持久购物车 |

## 13. 变更管理

1. 需求变更需更新本文档版本号与修订记录，并同步 README 中受影响的说明。
2. 定位器变更只修改 `config/locators/`，变更后必须单跑相关用例并完成全量回归。
3. 页面对象接口变更需同步更新调用它的测试用例与 README 速查表。
4. 新增用例必须补齐优先级标记，并同步更新第 7 节、`docs/需求追踪矩阵.md` 与 README 用例矩阵；随后执行 `python tools/verify_traceability.py` 确认无偏差。
5. 依赖升级需重新执行全量回归，并更新 `requirements.txt` 与兼容性说明。
6. CI 启用后，PR 必须通过 smoke 才能合并。
