# SauceDemo UI 自动化项目需求追踪矩阵

> 需求基线：`docs/需求规格说明书.md` V1.1（2026-11-17）
> 校验方式：`python tools/verify_traceability.py`（23 项静态与收集校验，含单元测试收集）+ `pytest -c pytest-unit.ini`（32 条配置层单测）+ `pytest -v`（20 条 UI 执行校验）
> 当前结论：20 条用例、SRS 用例表、RTM、源码标记与 pytest 收集结果全部对齐；2026-11-17 全量 20/20 通过；Chrome/Firefox 实跑与 CI 托管首跑待外部环境。

## 1. 追踪链路

```text
BR-01 ~ 05   业务需求：为什么做
      ↓
FR / NFR     功能与非功能需求：做到什么程度
      ↓
TC-001 ~ 020 测试用例：验证什么业务结果
      ↓
pytest 节点  可执行的唯一标识
      ↓
执行结果     通过 / 失败 + 失败产物
```

追踪原则：

- 每个 TC 至少关联一个 BR 或 FR，避免“有用例但无需求依据”。
- 每个 FR 组在本文第 4 节有明确的实现位置与验证方式，允许由框架验证而非单条 TC 验证。
- TC 的测试节点必须能在 `pytest --collect-only` 中精确找到，参数化用例展开后单独计数。
- 用例标记必须同时满足 SRS 的优先级（P0/P1/P2）与执行集（smoke/regression）。

## 8. 复现与校验命令

```bash
# 一键交叉校验（SRS / RTM / 收集 / 标记 / README / 需求覆盖 / 单元测试 / 分层约束）
python tools/verify_traceability.py

# 配置层单元测试（32 条，不启动浏览器）
pytest -c pytest-unit.ini -v

# 查看实际收集的 20 个节点（不生成报告）
pytest --collect-only -q -o addopts=

# 查看各执行集数量
pytest --collect-only -q -m smoke -o addopts=
pytest --collect-only -q -m p1 -o addopts=

# 执行全量并生成报告
pytest -v
```

## 9. 变更同步规则

1. 新增或删除用例：同步更新 SRS 第 7.1 节、本矩阵第 2 节、README 第 6.1 节，并调整 `tools/verify_traceability.py` 中的预期数量与标记统计。
2. 调整优先级或标记：同步 SRS、本矩阵、README 与校验脚本，重新执行 `pytest --collect-only` 确认数量。
3. 新增需求编号：在 SRS 中定义后，必须在本矩阵第 2 节或第 4 节建立实现位置与验证方式。
4. 修改测试函数名或参数化 ID：同步 SRS 测试列、本矩阵测试节点，否则校验脚本会直接失败。
5. 定位器或页面对象接口变化：按 SRS 第 13 节变更管理执行，单跑相关用例后再全量回归。
