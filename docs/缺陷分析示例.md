# 缺陷分析示例

本文件记录项目在实现与验收过程中真实发生的问题，按“现象 → 证据 → 时间线 → 定位 → 根因判断 → 处置决策 → 复盘”组织。所有证据均来自本仓库运行产物或 GitHub Actions 运行记录，未使用虚构数据。

- 分析日期：2026-11-17
- 运行环境：Windows 11、Python 3.13.12、Selenium 4.52.0、pytest 9.2.0、Edge 157.0.4341.60（headless）
- 被测站点：https://www.saucedemo.com/（公网共享演示站）
- 关联需求：NFR-01 稳定性、NFR-02 执行效率、FR-DIA-01~09 诊断与产物、FR-CI-01~03 持续集成

## DEF-01 公网站点瞬时不可达导致全量运行单点失败

### 现象

2026-11-17 14:16 的验收全量运行中，`tests/test_cart.py::test_add_single_item_to_cart` 失败，其余用例正常。失败发生在登录页加载阶段，页面停留在站点根地址，未进入商品页。

### 证据

失败元信息 `reports/runs/final-acceptance-20261117/20261117-141627_tests_test_cart.py__test_add_single_item_to_cart.json`：

```json
{
  "run_id": "final-acceptance-20261117",
  "nodeid": "tests/test_cart.py::test_add_single_item_to_cart",
  "saved_at": "20261117-141627",
  "current_url": "https://www.saucedemo.com/",
  "title": "www.saucedemo.com",
  "browser": "edge",
  "browser_version": "157.0.4341.60"
}
```

同一 `run_id` 的 `ui-tests.log` 前 5 行：

```text
14:16:15,152 INFO  conftest | Run config: env=demo base_url=https://www.saucedemo.com browser=auto headless=True
14:16:15,153 INFO  driver   | browser.name=auto resolved to: edge
14:16:16,240 INFO  driver   | WebDriver created: browser=edge version=157.0.4341.60 headless=True
14:16:16,255 INFO  page     | navigate https://www.saucedemo.com/
14:16:27,694 ERROR artifacts | Failure artifacts saved: .../20261117-141627_tests_test_cart.py__test_add_single_item_to_cart.png
```

失败截图保存在 `reports/runs/final-acceptance-20261117/screenshots/20261117-141627_tests_test_cart.py__test_add_single_item_to_cart.png`。

### 时间线

| 时间 | 事件 |
|---|---|
| 14:16:15 | 全量运行启动，配置解析完成 |
| 14:16:16 | WebDriver 创建成功，导航到站点根地址 |
| 14:16:16 ~ 14:16:27 | 等待登录页可交互元素，约 11s 后超时 |
| 14:16:27 | 保存失败截图与元信息；`current_url` 仍为 `/` |
| 14:16:30 | 单条复跑启动 |
| 14:16:33 | 单条复跑登录成功，7.41s 通过 |
| 14:16:55 ~ 14:18:46 | 全量重跑，20/20 通过（158.04s） |

### 定位过程

1. 检查失败截图与 `current_url`：页面没有跳转，`title` 为站点默认标题，说明浏览器已打开但页面资源未完整加载。
2. 检查日志：失败前只有 `navigate`，没有 `Login submitted`，说明等待登录页元素阶段超时，而非断言失败或定位器失效。
3. 单条复跑同一用例：7.41s 通过，排除代码与定位器问题。
4. 全量重跑：20/20 通过，排除顺序依赖与购物车状态污染。
5. 同一时段内其他用例登录正常，站点并非整体不可用。

### 根因判断

公网共享演示站出现瞬时连接/加载抖动，页面在显式等待窗口内未达到可交互状态。属于环境侧瞬时问题，不是产品缺陷，也不是自动化脚本缺陷。

### 处置决策

- **不引入自动重试**：重试会掩盖真实的加载与等待问题，且与项目“失败先修等待和定位器”的约定冲突。
- **保留失败现场**：截图、元信息、日志已按 `run_id` 归档，后续复盘可直接使用。
- **验证隔离性**：单条复跑 + 全量重跑确认无代码回归后，才更新验收记录。
- **观察而非掩盖**：在 SRS 8.2 与 README 中记录该现象与复跑结论。

### 复盘

- 显式等待已经覆盖页面状态，但无法消除公网链路本身的抖动；这类失败应在报告中明确标注为环境瞬时问题。
- 失败产物归档机制按预期工作，`run_id`、`nodeid`、`current_url`、浏览器版本齐备，满足可复盘要求。

## DEF-02 新增风险用例首轮批量失败（连接被关闭）

### 现象

2026-11-17 16:42 首次执行新增的 6 条风险型用例（TC-021 ~ TC-026），4 条失败、2 条通过。失败集中在页面导航与登录阶段，报错为 `net::ERR_CONNECTION_CLOSED`。

### 证据

`reports/runs/new-cases-20261117/report.html` 中失败用例的异常链：

```text
selenium.common.exceptions.WebDriverException: Message: unknown error: net::ERR_CONNECTION_CLOSED
  (Session info: MicrosoftEdge=157.0.4341.60)
```

首轮失败用例与现场地址：

| 用例 | 失败现场 `current_url` |
|---|---|
| `test_direct_protected_page_requires_login` | `https://www.saucedemo.com/inventory.html` |
| `test_product_detail_add_to_cart_updates_badge_and_list` | `https://www.saucedemo.com/` |
| `test_cart_page_refresh_keeps_items` | `https://www.saucedemo.com/` |
| `test_cancel_from_overview_returns_to_products_with_items` | `https://www.saucedemo.com/` |

首轮执行统计：6 tests，36s，4 failed / 2 passed（`reports/runs/new-cases-20261117/report.html`）。

### 时间线与复跑结果

| 运行 | 范围 | 结果 | 耗时 |
|---|---|---|---|
| `new-cases-20261117` | 6 条新增用例 | 4 failed / 2 passed | 36s |
| `new-cases-20261117b` | 4 条失败用例 | 1 passed / 3 failed（直连保护用例通过） | 26s |
| `new-cases-20261117c` | 3 条失败用例 | 2 passed / 1 failed（详情页加购、购物车刷新通过） | 21s |
| `new-cases-20261117d` | 概览取消用例 | 1 failed | 5s |
| `new-cases-20261117e` | 概览取消用例 | 1 passed | 8s |

每条新增用例至少通过一次；失败在复跑中随机漂移，未固定复现。

### 定位过程

1. 首轮失败地址既有 `/` 也有 `/inventory.html`，说明失败点随执行时机变化，不是单一页面元素问题。
2. 异常为 `WebDriverException: net::ERR_CONNECTION_CLOSED`，属于浏览器网络层错误，不是 `NoSuchElementException` 或断言失败。
3. 失败用例在后续复跑中通过，且通过的用例组合不断变化。
4. 新增页面对象（`ProductDetailPage`）与新增定位器在通过的运行中均正常工作，日志可见 `Opened product detail`、`Added to cart from product detail`、`Cart page refreshed`。

### 根因判断

在站点瞬时不可达窗口内，新增用例因首次访问页面更多、导航次数更多，命中概率高于既有用例。根因与 DEF-01 相同：公网演示站网络抖动，非脚本缺陷。

### 处置决策

- 保持串行执行与独立会话，不引入重试或 `sleep`。
- 通过分组复跑取得每条用例的有效通过证据，并在文档中如实记录失败与复跑过程。
- 将“公网站点抖动”列为已知风险，写入 SRS 第 11 节风险表和 8.2 待补证据。

### 复盘

- 新增用例的稳定性验证需要区分“首次命中失败”与“稳定复现失败”；本次全部属于前者。
- 报告内嵌的异常链与现场元信息足以在无终端输出的情况下完成定位，验证了 P0 报告升级的价值。

## DEF-03 失败证据无法进入 pytest-html 报告

### 现象

P0 阶段为报告增加“失败截图 + 现场 JSON + 日志尾部”内嵌能力。首次实现后，失败用例的 HTML 报告中没有出现预期附件，但磁盘上截图与 JSON 已正常生成。

### 证据

- 失败产物目录 `reports/runs/<run_id>/` 中存在 PNG 与 JSON。
- `report.html` 中没有对应的 extras 区块，报告中仅有异常堆栈。

### 定位过程

1. 确认 `extras.image` / `extras.text` 调用未抛异常。
2. 检查挂载时机：最初在 `driver` fixture 的 teardown 中读取浏览器并截图；此时 pytest 已执行完 call 阶段报告，而且浏览器可能已 `quit()`。
3. 检查 pytest-html 实现：其 `pytest_runtest_makereport` 为 `tryfirst` 的 hookwrapper，在 `yield` 返回后立即读取 `report.extras` 生成 HTML。非 `tryfirst` 的 hookwrapper 在它之后恢复执行，写入的 extras 不会被渲染。
4. 浏览器生命周期：`driver` fixture 在用例结束后 `quit()`，teardown 阶段再截图只能得到失效会话。

### 根因判断

两个工程问题叠加：

1. **挂载时机错误**：证据采集放在 fixture teardown，晚于报告生成。
2. **钩子顺序错误**：证据写入发生在 pytest-html 读取 `report.extras` 之后。

### 修复方案

- 在 `tests/conftest.py` 的 `pytest_runtest_makereport` 中，以**非 `tryfirst` 的 hookwrapper** 监听 `call` 阶段失败，在 `yield` 返回后立即采集并写入 `report.extras`。
- 采集时浏览器尚未销毁（fixture teardown 尚未执行），可正常截图、读取元信息与日志尾部。
- 一次采集同时产出磁盘归档与报告内嵌两份证据，避免重复截图。
- 异常处理只记录 warning，不因证据采集失败而改变用例结论。

### 验证

- 注入一条临时断言失败用例：报告中出现“失败截图 (PNG)”“失败现场信息 (JSON)”“运行日志尾部 (80 行)”三个区块。
- 删除临时用例后执行全量回归，通过数与标记统计不受影响。

### 复盘

- 报告插件类需求必须先确认钩子顺序与 fixture 生命周期，再写采集逻辑。
- 证据采集与磁盘归档共用一次快照，既保证一致性，也避免对被测页面重复操作。

## DEF-04 CI 首跑 Chrome smoke 失败（站点瞬时不可达）

### 现象

GitHub Actions 第 1 次运行（push 触发）中，`Smoke / chrome` 失败，`Unit tests` 与 `Smoke / firefox` 通过。失败步骤仅输出通用退出码，未提供页面级错误。

### 证据

- 运行 #1（2026-11-17T07:05:59Z ~ 07:07:00Z）：`Smoke / chrome` 结论 `failure`，同批次 Firefox smoke 与 unit 通过。
- 失败步骤注解仅有 `Process completed with exit code 1.`；未认证访问无法读取完整 job 日志。
- 紧接着的 run #2、run #3（push）中，Chrome/Firefox smoke 与 unit 全部通过；run #5、run #7（workflow_dispatch）中 Chrome/Firefox 全量 regression 全部通过。

### 定位过程

1. 同一提交下 Firefox smoke 通过，排除代码与用例逻辑对 Chrome 的必然不兼容。
2. 首跑后紧接的两次 push 运行全部通过，未做任何代码修改，排除稳定复现的脚本缺陷。
3. 本机保留的同类失败现场（DEF-01）显示失败发生在页面加载阶段，`current_url` 停留在站点根地址，与公网站点瞬时不可达特征一致。
4. 失败 job 的超时时间与正常 job 耗时对比未发现资源耗尽迹象。

### 根因判断

与 DEF-01 同类：CI runner 访问公网演示站时出现瞬时不可达。由于未保存 job 级页面证据，根因判断基于同时段对照运行与本地同类现场，置信度为“高但非直接证据”。

### 处置决策

- 不因一次瞬时失败修改用例或增加重试。
- 保留失败注解与运行编号，在验收文档中如实记录；以连续通过的 run #2/#3/#5/#7 作为 CI 可用性证据。
- 后续 CI 失败时优先下载 `reports/runs/` 产物，用截图与元信息替代不可访问的 job 日志。

### 复盘

- CI 与本地使用同一套失败产物归档机制，是跨环境定位的关键。
- 对公网演示站的 CI 稳定性预期应包含“偶发瞬时失败”，验收结论以多次运行与复跑为准。

## 汇总

| 编号 | 问题 | 类型 | 根因 | 处置 | 状态 |
|---|---|---|---|---|---|
| DEF-01 | 验收全量单点失败 | 环境瞬时 | 公网站点加载抖动 | 单条复跑 + 全量重跑，不加重试 | 已闭环 |
| DEF-02 | 新增用例首轮 4 条失败 | 环境瞬时 | `net::ERR_CONNECTION_CLOSED` | 分组复跑至每条通过，记录过程 | 已闭环 |
| DEF-03 | 报告缺少失败证据 | 工程缺陷 | 采集时机晚于报告生成、钩子顺序错误 | 改为 makereport call 阶段非 tryfirst hookwrapper | 已修复并验证 |
| DEF-04 | CI 首跑 Chrome 失败 | 环境瞬时 | 站点瞬时不可达（间接证据） | 复跑验证，保留归档机制 | 已闭环 |

共同结论：

1. 公网演示站的偶发不可达是本项目最主要的外部不稳定来源，处理原则是**保留证据、隔离复跑、不引入重试掩盖**。
2. 失败产物（截图、元信息、日志、HTML 报告内嵌证据）在本地与 CI 两个环境均能支撑定位。
3. 工程缺陷与产品/环境问题必须分开记录：DEF-03 属于自动化框架自身缺陷，已通过代码修复；DEF-01/02/04 不属于产品缺陷。
